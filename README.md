# Mage Wars Spellbook Builder

A phone-first spellbook builder for Mage Wars Arena, made for the cckarchev club. Pick a mage, build a 120-point spellbook from the full catalog, and share it as a link or as plain text for WhatsApp.

It is a static site with no backend. The book being built is kept in the browser's `localStorage`.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Starts the dev server |
| `npm test` | Runs the tests once (`npm run test:watch` keeps them running) |
| `npm run lint` | Checks lint and formatting with Biome (`npm run lint:fix` fixes what it can) |
| `npm run typecheck` | Type checks the app and the scripts |
| `npm run build` | Type checks and builds the site into `dist/` |
| `npm run data` | Regenerates the card data and images (see below) |

## Card data

`src/data/cards.json` and `public/cards/*.webp` are generated by `npm run data` (`scripts/buildData.ts`) from the OCTGN Mage Wars module. They are committed, so the app builds without the raw files.

To regenerate them, put these in `raw-input/` (git-ignored):

- `mage-wars-3.1.4.1.nupkg`: the OCTGN module.
- `MW_Card_Image_Pack.o8c`: the community image pack.
- `legacy-sets/`: the older set files. The script downloads them from [sIKE23/Mage-Wars](https://github.com/sIKE23/Mage-Wars) when the folder is missing.

The script cuts the white or transparent frame some pack images have and rewrites every image, so a full run takes about a minute.

The mages (`src/data/mages.ts`) are written by hand from each mage's stats card in the module.

## Rules

Point costs follow the module's spellbook validator (`SpellbookValidator.py`). "Only" cards follow the card text. The questions where the module and the cards disagree are listed in the app, below the mage picker, for players to confirm.

## Embedding

The club site shows the builder in an iframe and passes its own page as `?embed=<url-encoded page>`. Share links then point back at that page. Only `cckarchev.ar` (and `localhost` for local work) are accepted as embedding pages.

## Code layout

- `src/core/`: pure logic with its tests (rules, catalog search, share link, text export).
- `src/features/`: screens and their components.
- `src/components/`: shared UI primitives.
- `src/store/`: the book store.
- `scripts/`: the data pipeline.
