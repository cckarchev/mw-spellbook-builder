# Mage Wars Spellbook Builder

A phone-first spellbook builder for Mage Wars Arena, made for the cckarchev club. Pick a mage, build a 120-point spellbook from the full catalog, and share it as a link or as plain text for WhatsApp.

It is a static site with no backend, live at [mw-spellbook-builder.cckarchev.ar](https://mw-spellbook-builder.cckarchev.ar). Everything is kept in the browser's `localStorage`: each mage has its own draft, saved on every change, and its own named spellbooks, saved from the actions under the spellbook header.

## Stack

- **React 19** + **TypeScript**
- **Vite** (dev server + build)
- **CSS Modules**, styled with the club's shared tokens (see Design system)
- **Zustand** for state (`src/store/`) and **React Router** for routing
- **Vitest** + **React Testing Library** for tests, and **Biome** for lint and format, from the shared preset in [`@cckarchev/shared`](https://github.com/cckarchev/cck-shared)
- **[Cloudflare Workers](https://workers.cloudflare.com)** with static assets, via Wrangler, deploy

## Commands

Requires Node 24.21 or later (`.node-version`).

| :------------------- | :-------------------------------------------------- |
| `npm install`        | Install dependencies                                |
| `npm run dev`        | Dev server at `localhost:5173`                      |

| `npm run data`       | Regenerate the card data and images (see below)     |

## Project layout

- `src/core/`: pure logic with its tests (rules, catalog search, share link, text export, drafts and saved spellbooks).
- `src/features/`: screens and their components.
- `src/components/`: shared UI primitives.
- `src/layout/`: the app shell.
- `src/theme/`: global styles, breakpoints and the app tokens.
- `src/store/`: the spellbook store, which keeps the open spellbook in its mage's draft.
- `scripts/`: the data pipeline.

Imports inside one area are relative; imports that leave it use the `@/` alias for `src/`.

## Card data

`src/data/cards.json` and `public/cards/*.webp` are generated by `npm run data` (`scripts/buildData.ts`) from the OCTGN Mage Wars module. They are committed, so the app builds without the raw files.

To regenerate them, put the community image pack at `raw-input/MW_Card_Image_Pack.o8c` (`raw-input/` is git-ignored). The script downloads the rest into the same folder when it is missing:
- `mage-wars-3.1.4.1.nupkg`: the OCTGN module, from the OCTGN game feed.
- `legacy-sets/`: the older set files, from [sIKE23/Mage-Wars](https://github.com/sIKE23/Mage-Wars), used for the expansion names.

The script cuts the white or transparent frame some pack images have and rewrites every image, so a full run takes about a minute.

Where the module's text disagrees with the card image (a missing attack bar, a misprinted trait), `scripts/lib/cardCorrections.ts` holds the fix, copied by hand from the image. The script stops if a correction no longer matches its card.

The glossary (`src/data/glossary.json`) comes from the Mage Wars Codex: put it at `raw-input/Mage_Wars_Codex.pdf`. The script reads it with `pdftohtml`, from poppler-utils, which tells the terms apart from their definitions by their font.

The mages (`src/data/mages.ts`) are written by hand from each mage's stats card in the module. Each one names two cards, the mage picture for the table and the stats card, and the script extracts both images.

The official spellbooks (`src/data/officialSpellbooks.json`) come from the module's `def/Decks/Official Spellbooks/` folder, one per mage, as card id to copies. Some decks list a card under the id of another printing, so the script matches each card by id first and then by its exact name among the Arena cards. It stops, naming the deck and the card, when a card or a mage does not match.

## Rules

Point costs follow the module's spellbook validator (`SpellbookValidator.py`), with two corrections the players confirmed where the module and the cards disagree:
- "X Only" cards follow the card text: only the mage named on the card can use it, so a Warlock cannot take Death Ring (Necromancer Only). "Holy Mage Only" and similar cards go to any mage trained in that school, including partial training, so the Paladin can take Holy and War Mage Only cards (above level 2 they cost double).
- Each part of an "and" card is charged its own multiplier. An opposed part stays triple even when another part is within partial training, so Gerard Matranga costs the Druid 7 points, not the module's 5.

## Deploy

The site runs on Cloudflare Workers as static assets only, with no Worker script. `wrangler.jsonc` serves `dist/`, falls back to `index.html` for the app's routes, and attaches the custom domain `mw-spellbook-builder.cckarchev.ar`.

`npm run deploy` verifies, builds and uploads it with the project's own Wrangler. Log in once with `npx wrangler login` on an account that holds the `cckarchev.ar` zone.

## Design system

The UI follows the club's design system: dark-only theme, sharp corners, orange accent over a near-black base. The palette, scales and fonts come from [`@cckarchev/shared`](https://github.com/cckarchev/cck-shared) (`fonts.css` and `tokens.css`, imported in `src/main.tsx`). `src/theme/tokens.css` only adds the tokens specific to this app.
